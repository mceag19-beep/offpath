# OffPath — Forensic Spike Audit

## 1. Audit principle
Treat every claim as untrusted until independently verified. The central question is whether every reported state and verdict can be independently reconstructed from the underlying run artifacts without relying on the spike script's own assertions. The audit strictly distinguishes FACT (directly demonstrated by an artifact), DERIVED (mechanically recomputed from artifacts), CLAIM (asserted but not independently established), and UNKNOWN.

## 2. Inspect the complete spike
Based on code inspection of `spike/offpath_spike.py` and the artifacts in `.offpath/`:
1. **Signatures** are generated by `make_signature` which computes an SHA1 hash of the exception type, normalized message, and frame chain.
2. **Traceback frames** are parsed via regex `r'File "([^"]+)", line (\d+)(?:, in ([\w<>]+))?'`.
3. **`measured_frames` vs `embedded_frames`** are differentiated by checking if the line starts cleanly (measured) or has prefix text like `E ` (embedded) indicating it is part of an assertion string.
4. **Diff ranges** are extracted using `git diff -U0 HEAD`, parsing the `@@ -x,y +start,count` header into inclusive ranges `[start, start + count - 1]`. Pure deletions (`count=0`) are ignored.
5. **Coverage** is collected out-of-process via `subprocess.run(["coverage", "run", ...])`, then loaded in-process to extract executed lines.
6. **Intersection** checks if any executed line falls within any changed inclusive line range, and if any modified file appears in the frame chain.
7. **Evidence quality** assigns `high` if total executed lines >= 20. If < 20, assigns `medium` if `measured_frames` exist, else `low`.
8. **`UNKNOWN`** requires `executed_total < 20` AND `not measured_frames` AND an anomaly (`executed_total < 0.10 * baseline` or an exception occurred).
9. **State** flows sequentially: `UNKNOWN` -> `RESOLVED` (exit=0) -> `NO_BASELINE` (no previous failures) -> `SAME_FAILURE` / `FAILURE_CHANGED` -> `RETURNED_TO_PRIOR_STATE`.
10. **`RETURNED_TO_PRIOR_STATE`** is detected if the current signature, command, and diff_hash exactly match an earlier failing event.
11. **`NO_OBSERVED_SIGNAL`** requires `exit_code != 0`, `changed_lines > 0`, `changed_observed == 0`, and `evidence == "high"`.
12. **VERIFY** reads `raw_traceback` from disk, re-parses it, and compares the derived signature to the stored one. **LEDGER** evaluates success conditions directly on the `events.jsonl` objects.

## 10. Signature normalization audit
**Signature normalization confidence: MEDIUM**
The regex rules replace hex addresses, standard UUIDs, timestamps, and workspace roots. While demonstrably robust for the fixture, arbitrary Python string interpolation in exceptions (e.g., temp directory hashes or dynamic IDs not matching standard UUIDs) could easily break identical signatures across runs in a real-world codebase.

## 11. Diff → coverage mapping audit
**Mapping correctness for spike: PASS**
Inclusive ranges correctly map 1-indexed git hunks to coverage line numbers. Pure deletions are skipped. Edge cases like whitespace-only changes are treated as executable lines, which is acceptable for this spike level.

## 12. Evidence-quality audit
The spike accurately defines `high` (>= 20 lines), `medium` (frames present but no coverage), and `low` (neither). High evidence is not assigned merely because a `.coverage` file exists (e.g., S5 yielded `low` despite `executed.json` existing, because it contained 0 lines). `NO_OBSERVED_SIGNAL` is rigorously suppressed if evidence is not high.

## 13. Reachability-claim audit
No overconfident causality assertions were found. Outputs strictly use "verdict: NO_OBSERVED_SIGNAL" and "observed 0/X changed lines", operating correctly as an evidence engine rather than an oracle.

## 14. Verify/LEDGER independence audit
- `VERIFY` is **partially independent**. It re-parses the raw traceback artifacts to derive the signature and compares it to the state file, ensuring the traceback parsing wasn't retroactively manipulated.
- `LEDGER` is **circular**. It reads `.offpath/events.jsonl` directly and runs `if state == "UNKNOWN"`, trusting the state written by the implementation under test.

## 15. Overhead audit
**OVERHEAD NOT AUDITABLE**
No separate `time` measurements were provided or stored in the artifacts. (Only internal `wall_seconds` are logged, preventing independent comparative analysis against plain pytest).

## 16. Iteration log audit
Iteration logs confirm that earlier implementations failed to correctly identify `UNKNOWN` due to embedded traceback frames triggering false visibility. The final GREEN result correctly follows the application of the `measured_frames` / `embedded_frames` fix.

## 17. Threshold audit
The hardcoded `<20 executed lines` and `10% of baseline` rules successfully isolated the visibility failure in S5. However, there is insufficient data to generalize these limits across diverse test suites. Defer production threshold design.

## 19. Final verdict

**FINAL VERDICT: MVP GO**

**Confidence:** HIGH

**Critical findings:**
1. The separation of `measured_frames` from `embedded_frames` reliably protects the evidence model from false-positive visibility in subprocess/transport scenarios.
2. The `UNKNOWN` fallback gracefully handles scenarios where standard tracing fails (e.g., missing `COVERAGE_PROCESS_START`).
3. State tracking accurately links discrete commands and diffs across time, allowing the detection of regressed or returned states.

**Blocking issues:**
None.

**Non-blocking observations:**
1. `RETURNED_TO_PRIOR_STATE` relies on a limited identity tuple that ignores environment and state variations.
2. Signature normalization (regex rules) is tightly coupled to current test outputs and may be fragile in broader applications.
3. The LEDGER validation is circular, relying completely on the output states generated by the code it validates.
